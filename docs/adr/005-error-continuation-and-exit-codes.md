# ADR-005: 複数URL指定時におけるエラー継続制御（部分成功方式）および終了コード優先度仕様

## ステータス (Status)
**承認済み (Accepted)**

## 文脈と課題 (Context)
要件定義書およびシステム設計書では、引数として複数のフィードURLを指定し、一括取得して単一ストリームに出力する機能が定義されている[cite: 3, 4]。しかし、従来のシーケンス図ではいずれか1件のURLでエラー（接続失敗、タイムアウト、パース失敗等）が発生した時点で即座にプロセスを終了コード2〜4で異常終了させるフェイルファスト（Fail-Fast）設計となっていた[cite: 1, 3, 4]。

この仕様には以下の課題が存在した：
1. **巡回収集・バッチ処理の実用性欠如**: 複数サイトを巡回収集する際、一時的な1サイトのネットワーク不調や404エラーによって全体の処理が即座に中断され、正常に取得できた他サイトのフィードデータまで破棄されてしまう[cite: 1, 3, 4]。
2. **入出力ストリーム制御との整合性**: 標準出力に正常データのみを出力し、標準エラー出力にエラーログを出力するという物理分離の原則を維持しつつ、部分的に取得できたデータを後続ツール（`jq` 等）へ安全に引き渡す挙動が未定義であった[cite: 1, 3, 4]。

## 決定事項 (Decision)
複数URL指定時における処理制御として**「エラースキップによる部分成功（ベストエフォート）方式」**を採用する。

1. **入出力ストリーム制御仕様**:
   * **標準出力（stdout） / ファイル出力（`-o`）**: 正常に取得・パースに成功したフィード記事のみをフォーマット（JSON / CSV）して出力する[cite: 1, 3, 4]。取得に失敗したURLの記事は含まれない[cite: 1, 4]。
   * **標準エラー出力（stderr）**: 各URLの処理中にエラーが発生した都度、規定のエラープレフィックス（`Error: network failure:`、`Error: request timed out:`、`Error: failed to parse feed:`）を付与して即時出力する[cite: 1, 3, 4]。
2. **終了コードの決定ルール**:
   * **全URL成功時**: 終了コード `0` を返却する[cite: 1, 3, 4, 5]。
   * **一部または全URL失敗時**: 発生したすべてのエラーの中で、**最も優先度が高い終了コード**をプロセスの最終終了コードとして返却する[cite: 1, 3, 4, 5]。
   * **優先度順位**:
     $$\text{Code 1 (引数不正)} > \text{Code 2 (ネットワークエラー)} > \text{Code 3 (タイムアウト)} > \text{Code 4 (パースエラー)}$$
[cite: 1, 3, 4, 5]
   * （※引数構文やフラグ値の不正による Code 1 は、CLI開始時のバリデーション段階で判定され即時終了する[cite: 1, 3, 4]）

## 結果と影響 (Consequences)
### メリット (Positive)
* **自動化耐性の向上**: 一時的な単一サイト障害が発生しても、取得可能なフィードデータは確実に標準出力経由で下流パイプラインへ流すことが可能となる[cite: 3, 4]。
* **ストリーム分離の厳格な維持**: 標準出力に壊れたデータやログが混入せず、標準エラー出力へのみエラー詳細が集約される[cite: 1, 3, 4]。

### デメリット・トレードオフ (Negative / Risks)
* **呼出元シェルスクリプトの注意点**: 終了コードが非0であっても標準出力に部分的なデータが存在し得るため、呼び出し側は「完全成功のみ受け入れるか」「部分成功データも利用するか」に応じた終了コードハンドリングが必要となる。
