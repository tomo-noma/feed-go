# ADR-001: コマンドラインフィード取得ツールのアーキテクチャおよび基本仕様の策定
## ステータス (Status)
### 承認済み (Accepted)

## 文脈と課題 (Context)
コマンドラインインターフェース（CLI）を通じて指定されたURLからWebフィードを取得・パースし、JSONまたはCSV形式で標準出力・ファイル出力するツールを新規開発する。
シェルスクリプトやパイプライン処理、定期バッチ処理などの自動化ワークフローに組み込まれることを想定しており、高速な起動性、容易なポータビリティ、および堅牢な入出力制御が求められる。

- **機能要件:**
  - コマンドラインから実行可能であること。
  - URLを指定してフィード（RSS/Atom）を取得できること。
  - JSONおよびCSVの2種類のフォーマットで出力できること。

- **非機能要件:**
  - 1サイトあたりのフィード取得を10秒以内に完了すること（タイムアウト制御）。
  - 単一バイナリ配布が可能で、起動オーバーヘッドが小さいこと。
  - パイプライン連携に適した標準入出力・終了コードの挙動を担保すること。

## 決定事項 (Decision)
1. 実装技術スタック
  - **実装言語:** Go
    - **採用理由:**
      - クロスコンパイルによるOS/アーキテクチャ別（Linux, macOS, Windows）の単一実行バイナリ生成が容易であり、ユーザー環境へのランタイム導入が不要。
      - プロセス起動が極めて高速で、シェルスクリプトやCLIパイプライン連携に適している。
      -標準パッケージ（net/http, encoding/csv, encoding/json）が強固であり、外部依存を最小限に抑えられる。

  - **推奨ライブラリ:**
    - CLIフレームワーク: spf13/cobra または urfave/cli
    - フィード解析: mmcdole/gofeed（RSS 0.9x, 1.0, 2.0, Atomを網羅）

2. CLIインターフェースと入出力設計
  - コマンド基本構文:
```Bash
feed-go [OPTIONS] <URL...>
```

  - 入出力ストリームの分離:
    - `stdout`: 正常なフィードデータ（JSON / CSV）のみを出力。`jq`やリダイレクト処理を妨げない。
    - `stderr`: エラーメッセージ、進捗情報、警告を出力。

  - 主要オプション:
    - `-f, --format <json|csv>`: 出力形式の指定（デフォルト: json）。
    - `-o, --output <FILE>`: 出力先ファイルパス（未指定時は stdout）。
    - `-t, --timeout <SEC>`: タイムアウト秒数（デフォルト: 10）。
    - `-l, --limit <NUM>`: 取得記事数の上限指定。

3. 出力フォーマット仕様（JSON / CSV）
  - 共通データスキーマ:
    フィード規格ごとの差異を以下の共通構造体にマッピングして出力する。

    - `title`: 記事タイトル（string）
    - `url`: 記事URL（string）
    - `published_at`: 公開日時（string, ISO 8601形式: `YYYY-MM-DDTHH:mm:ssZ`）
    - `summary`: 記事本文・概要（HTMLタグを除去したプレーンテキスト）
    - `author`: 著者名（string / 空値許容）
    - `feed_title`: 配信元サイト名（string）

  - CSV出力仕様:
    - RFC 4180に準拠する。Goの標準パッケージ `encoding/csv` を使用し、カンマ、ダブルクォーテーション、および `summary` 内のセル内改行を適切にエスケープ処理する。
    - 1行目にはヘッダー行を出力する。

4. ネットワーク制御と非機能要件
  - 10秒タイムアウト制約の遵守:
    - Goの context.WithTimeout を用いてリクエスト全体の最大生存期間を10秒に制限する。
    - 内部内訳の目安: 接続タイムアウト（Connect）3秒、応答・読み込みタイムアウト（Read）7秒。超過時は即座にコンテキストを破棄しリソースを解放する。

  - HTTPクライアント設定:
    - User-Agentヘッダーを明示的に指定（例: feed-cli/1.0 (+[https://github.com/](https://github.com/)...)）。
    - リダイレクトは最大5回まで自動追跡。

  - 終了コード（Exit Codes）
    - `0`: 正常終了
    - `1`: 引数・オプション不正
    - `2`: ネットワークエラー（DNS解決失敗、HTTP 4xx/5xx）
    - `3`: タイムアウト（10秒超過）
    - `4`: パースエラー（XMLパース失敗、未知のフォーマット）

## 初期実装のスコープ外（今後の優先実装対象）
以下の2点はアーキテクチャの複雑化を防ぎ、まずは最小限で堅牢なMVP（Minimum Viable Product）を素早く完成させるため、初期リリースではスコープ外とする。ただし、次期バージョンにおいて最優先で実装する。

1. フィード自動検出（Auto-Discovery）:
   - 初期版はXML/フィードの直接URLのみを受け付ける。
   - 次期フェーズで、HTMLページ内の `<link rel="alternate" ...>` を解析して自動特定する機能を導入する。

2. 文字コード自動判別:
   - 初期版はUTF-8で配信されているフィードのみを対象とする。
   - 次期フェーズで、Shift_JISやEUC-JP等で配信される古い国内フィードの文字コード自動判別・UTF-8変換を導入する。

## 結果と影響 (Consequences)
### メリット (Positive)
- 高い可搬性と保守性: Goの単一バイナリによる配布により、Docker環境やCI/CD、ローカルマシンへの導入が curl や go install だけで完結する。
- 予測可能なデータ連携: RFC 4180準拠のCSVおよび統一スキーマのJSONにより、下流のデータパイプラインでの解析エラーを防止できる。
- 軽量・高速: 起動時間が数ミリ秒レベルのため、cron等での高頻度定期実行に適している。

### デメリット・トレードオフ (Negative / Risks)
- 初期版ではUTF-8以外のフィードを指定した場合に文字化けが発生する可能性がある（次期フェーズで解消予定）。
- フィードURLを直接指定する必要があるため、サイトトップのURLを指定された場合はパースエラーとなる（次期フェーズでAuto-Discovery導入予定）。
