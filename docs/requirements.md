# コマンドラインフィード取得ツール（feed-go）要件定義書

## 1. システム概要

### 1.1 システム名
コマンドラインフィード取得ツール（実行ファイル名: `feed-go`）

### 1.2 目的と背景
シェルスクリプト、データパイプライン、定期バッチ処理などの自動化ワークフローに組み込むことを想定し、指定されたWebフィード（RSS/Atom）を高速かつ確実に取得・パースし、JSONまたはCSV形式で標準出力・ファイル出力するCLIツールを開発する。

### 1.3 利用想定
- **パイプライン連携:** `feed-go https://example.com/feed.xml | jq .` のように、後続ツールへストリーム連携する。
- **定期自動実行:** cronやCI/CDパイプラインによる定期的な情報収集バッチ処理。
- **データ保管:** オプション指定により直接ファイルへ出力し、アーカイブや分析用データセットを作成する。

---

## 2. スコープ定義

### 2.1 初期リリース対象（MVP）
- コマンドラインからの単一/複数URL指定によるフィード取得
- RSS（0.9x, 1.0, 2.0）およびAtom形式のパース
- 共通データモデルへの正規化（HTMLタグ除去を含む）
- JSONおよびCSV（RFC 4180準拠）形式での出力（標準出力・ファイル出力）
- 10秒以内のタイムアウト制御およびHTTPリダイレクト制御
- 規定の終了コードによる実行結果の返却
- マルチプラットフォーム（Linux, macOS, Windows）向けの単一実行バイナリ提供

### 2.2 対象外（次期フェーズ優先実装）
- **フィード自動検出（Auto-Discovery）:** Webサイト（HTML）の `<link rel="alternate" ...>` タグを解析してフィードURLを特定する機能。初期版ではフィード（XML）の直接URLのみを受け付ける。
- **文字コード自動判別・変換:** Shift_JISやEUC-JP等で配信されるフィードのUTF-8自動変換。初期版はUTF-8配信のフィードのみを対象とする。

## 3. 機能要件

### 3.1 コマンドラインインターフェース（CLI）

#### コマンド構文
```bash
feed-go [OPTIONS] <URL...>
```

#### 引数・オプション仕様
| 引数 / オプション | 短縮形 | 引数値 | デフォルト値 | 必須 | 説明 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `<URL...>` | - | 文字列（URL） | - | ○ | 取得対象のフィードURL（1つ以上指定可能） |
| `--format` | `-f` | `json` \| `csv` | `json` | - | 出力フォーマットの指定 |
| `--output` | `-o` | ファイルパス | `stdout` | - | 出力先ファイルの指定。未指定時は標準出力 |
| `--timeout` | `-t` | 整数（秒） | `10` | - | リクエスト全体の最大待機時間 |
| `--limit` | `-l` | 整数（件数） | 無制限 | - | 取得・出力する記事数の上限 |
| `--help` | `-h` | - | - | - | ヘルプメッセージの表示 |
| `--version` | `-v` | - | - | - | バージョン情報の表示 |

### 3.2 入出力ストリーム制御
パイプライン処理およびシェルスクリプト連携を妨げないため、ストリームを厳格に分離する。

- **標準出力（stdout）:** 正常系データ（JSON / CSV）のみを出力する。
- **標準エラー出力（stderr）:** エラーメッセージ、進捗情報、警告を出力する。

### 3.3 フィード取得（ネットワーク制御）
- **プロトコル:** HTTP / HTTPS
- **User-Agent:** クライアント側で一意なUser-Agentヘッダーを送信する（形式: `feed-go/<version> (+https://github.com/...)`）。
- **リダイレクト:** HTTP 3xxリダイレクトを最大5回まで自動追跡する。6回以上のリダイレクト、または循環リダイレクト時はネットワークエラーとする。
- **タイムアウト内訳:**
  - 接続確立（Connect）: 最大3秒
  - レスポンス読み取り（Read）: 最大7秒
  - 合計待機時間は `--timeout` で指定された秒数（デフォルト10秒）を超過しない。超過時は即座にリクエストを中断し、内部リソースを破棄する。

### 3.4 フィード解析およびデータスキーマ
取得した各フィード規格（RSS 0.9x, 1.0, 2.0, Atom）の差分を吸収し、以下の統一スキーマに正規化する。

| フィールド名 | 型 | 必須 | 説明 | 備考 |
| :--- | :--- | :--- | :--- | :--- |
| `title` | string | ○ | 記事タイトル | 空文字の場合は空文字列を設定 |
| `url` | string | ○ | 記事のパーマリンクURL | - |
| `published_at`| string | ○ | 公開日時 | ISO 8601形式（`YYYY-MM-DDTHH:mm:ssZ`） |
| `summary` | string | ○ | 記事の概要・本文 | HTMLタグを除去したプレーンテキスト |
| `author` | string | - | 著者名 | 取得できない場合は空文字列を設定 |
| `feed_title` | string | ○ | 配信元のフィード名 | サイトのタイトル |

- **HTMLサニタイズ処理:** `summary` に含まれるHTMLタグ（`<p>`, `<a>`, `<script>` 等）をすべて除去し、プレーンテキストに変換する。

### 3.5 出力形式仕様

#### JSON出力
- 形式: 共通スキーマに基づいたオブジェクトの配列。
- 文字コード: UTF-8。

```json
[
  {
    "title": "リリースのお知らせ",
    "url": "https://example.com/articles/1",
    "published_at": "2026-09-30T16:00:00Z",
    "summary": "feed-goのv1.0が正式リリースされました。",
    "author": "管理者",
    "feed_title": "Example Official Blog"
  }
]
```

#### CSV出力
- **規格準拠:** RFC 4180に完全準拠。
- **ヘッダー行:** 1行目に `title,url,published_at,summary,author,feed_title` を常に出力。
- **エスケープ処理:** カンマ、ダブルクォーテーション（`"`）、および改行コードを含むフィールドは、フィールド全体をダブルクォーテーションで囲み、内部の `"` は `""` にエスケープする。
- **改行コード:** CRLF（`\r\n`）。

### 3.6 エラーハンドリングおよび終了コード
処理終了時、プロセスは状況に応じて以下の終了コードを返却する。

| 終了コード | 状態 | 発生条件 | stderr 出力例 |
| :---: | :--- | :--- | :--- |
| `0` | 正常終了 | すべてのフィード取得・出力が完了 | なし |
| `1` | 引数・オプション不正 | URL未指定、無効なオプション値、フラグ構文エラー | `Error: invalid argument: --format must be either 'json' or 'csv'` |
| `2` | ネットワークエラー | DNS解決失敗、ホスト接続不可、HTTP 4xx/5xx | `Error: network failure: GET https://example.com/feed failed with status 404` |
| `3` | タイムアウト | 接続または読み込みが制限時間（デフォルト10秒）を超過 | `Error: request timed out after 10s` |
| `4` | パースエラー | レスポンスがXML/フィードとして解析不能、未知のフォーマット | `Error: failed to parse feed from https://example.com/index.html` |

## 4. 非機能要件

### 4.1 性能要件
- **起動時間:** プロセス起動から実行完了までのオーバーヘッドを極小化（目標: 起動オーバーヘッド50ms以下）。
- **メモリ効率:** ストリーム処理を意識し、メモリ使用量は一般的なフィード（数百KB〜数MB）処理時に30MB以下に抑える。
- **処理速度:** ネットワーク遅延を除き、XML解析および出力変換処理を100ms以内に完了する。

### 4.2 移植性・運用環境要件
- **動作環境:**
  - Linux（x86_64, aarch64）
  - macOS（x86_64, arm64 / Apple Silicon）
  - Windows（x86_64）
- **配布形態:** 外部ランタイム（JVM、Pythonインタープリタ、Node.js等）を不要とし、依存ライブラリを静的リンクした単一バイナリ形式で配布する。
- **導入容易性:** OSごとの単一実行ファイルを `PATH` が通ったディレクトリに配置するだけで即座に利用可能であること。

### 4.3 信頼性・堅牢性
- **リソース解放:** タイムアウトまたはエラー発生時、Goの `context.WithTimeout` を通じてHTTP接続を即座に破棄し、ソケットのリークを防ぐ。
- **異常入力への耐性:** HTML混入や不正文字が含まれるフィードであっても、プロセスがパニック（異常終了）することなく、安全にサニタイズまたはエラーコードを返却する。

## 5. 技術選定・開発標準

| 領域 | 選定技術 / ライブラリ | 選定理由 |
| :--- | :--- | :--- |
| **開発言語** | Go (最新安定版) | 高速な起動性、メモリ安全性、容易なクロスコンパイル、単一バイナリ出力 |
| **CLIフレームワーク** | `spf13/cobra` または `urfave/cli` | POSIX準拠のフラグ解析、ヘルプ自動生成、サブコマンド拡張の容易性 |
| **フィードパーサー** | `mmcdole/gofeed` | RSS 0.9x/1.0/2.0、Atomを広くカバーし、パース精度が高い |
| **標準パッケージ活用**| `net/http`, `encoding/json`, `encoding/csv` | 外部依存を削減し、バイナリ肥大化とサプライチェーンリスクを抑制 |
