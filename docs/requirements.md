# コマンドラインフィード取得ツール（feed-go）要件定義書

## 1. システム概要

### 1.1 システム名
コマンドラインフィード取得ツール（実行ファイル名: `feed-go`）[cite: 6]

### 1.2 目的と背景
シェルスクリプト、データパイプライン、定期バッチ処理などの自動化ワークフローに組み込むことを想定し、指定されたWebフィード（RSS/Atom）を高速かつ確実に取得・パースし、JSONまたはCSV形式で標準出力・ファイル出力するCLIツールを開発する[cite: 6]。

### 1.3 利用想定
- **パイプライン連携:** `feed-go https://example.com/feed.xml | jq .` のように、後続ツールへストリーム連携する[cite: 6]。
- **定期自動実行:** cronやCI/CDパイプラインによる定期的な情報収集バッチ処理[cite: 6]。
- **データ保管:** オプション指定により直接ファイルへ出力し、アーカイブや分析用データセットを作成する[cite: 6]。

---

## 2. スコープ定義

### 2.1 初期リリース対象（MVP）
- コマンドラインからの単一/複数URL指定によるフィード取得[cite: 6]
- RSS（0.9x, 1.0, 2.0）およびAtom形式のパース[cite: 6]
- 共通データモデルへの正規化（HTMLタグ除去・空白改行正規化を含む）[cite: 1, 5, 6]
- JSONおよびCSV（RFC 4180準拠）形式での出力（標準出力・ファイル出力）[cite: 2, 6]
- 10秒以内のタイムアウト制御およびHTTPリダイレクト制御[cite: 2, 6]
- 規定の終了コードによる実行結果の返却[cite: 2, 6]
- マルチプラットフォーム（Linux, macOS, Windows）向けの単一実行バイナリ提供[cite: 1, 2, 6]

### 2.2 対象外（次期フェーズ優先実装）
- **フィード自動検出（Auto-Discovery）:** Webサイト（HTML）の `<link rel="alternate" ...>` タグを解析してフィードURLを特定する機能[cite: 2, 6]。初期版ではフィード（XML）の直接URLのみを受け付ける[cite: 2, 6]。
- **文字コード自動判別・変換:** Shift_JISやEUC-JP等で配信されるフィードのUTF-8自動変換[cite: 2, 6]。初期版はUTF-8配信のフィードのみを対象とする[cite: 2, 6]。

## 3. 機能要件

### 3.1 コマンドラインインターフェース（CLI）

#### コマンド構文
```bash
feed-go [OPTIONS] <URL...>
```
[cite: 2, 6]

#### 引数・オプション仕様
| 引数 / オプション | 短縮形 | 引数値 | デフォルト値 | 必須 | 説明 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `<URL...>` | - | 文字列（URL） | - | ○ | 取得対象のフィードURL（1つ以上指定可能） |
| `--format` | `-f` | `json` \| `csv` | `json` | - | 出力フォーマットの指定 |
| `--output` | `-o` | ファイルパス | `stdout` | - | 出力先ファイルの指定。未指定時は標準出力 |
| `--timeout` | `-t` | 整数（秒） | `10` | - | リクエスト全体の最大待機時間 |
| `--limit` | `-l` | 整数（件数） | 無制限 | - | 取得・出力する記事数の上限 |
| `--help` | `-h` | - | - | - | ヘルプメッセージの表示 |
| `--version` | `-v` | - | - | - | バージョン情報の表示 |
[cite: 2, 6]

### 3.2 入出力ストリーム制御
パイプライン処理およびシェルスクリプト連携を妨げないため、ストリームを厳格に分離する[cite: 2, 6]。

- **標準出力（stdout）:** 正常系データ（JSON / CSV）のみを出力する[cite: 2, 6]。
- **標準エラー出力（stderr）:** エラーメッセージ、進捗情報、警告を出力する[cite: 2, 6]。

### 3.3 フィード取得（ネットワーク制御）
- **プロトコル:** HTTP / HTTPS[cite: 1, 6]
- **User-Agent:** クライアント側で一意なUser-Agentヘッダーを送信する（形式: `feed-go/<version> (+https://github.com/...)`）[cite: 1, 2, 6]。
- **リダイレクト:** HTTP 3xxリダイレクトを最大5回まで自動追跡する[cite: 1, 2, 6]。6回以上のリダイレクト、または循環リダイレクト時はネットワークエラーとする[cite: 1, 6]。
- **タイムアウト内訳:**
  - 接続確立（Connect）: 最大3秒[cite: 1, 2, 6]
  - レスポンス読み取り（Read）: 最大7秒[cite: 1, 2, 6]
  - 合計待機時間は `--timeout` で指定された秒数（デフォルト10秒）を超過しない[cite: 1, 6]。超過時は即座にリクエストを中断し、内部リソースを破棄する[cite: 1, 2, 6]。

### 3.4 フィード解析およびデータスキーマ
取得した各フィード規格（RSS 0.9x, 1.0, 2.0, Atom）の差分を吸収し、以下の統一スキーマに正規化する[cite: 1, 2, 6]。

| フィールド名 | 型 | 必須 | 説明 | 備考 |
| :--- | :--- | :--- | :--- | :--- |
| `title` | string | ○ | 記事タイトル | 前後空白トリミング。空文字の場合は空文字列を設定 |
| `url` | string | ○ | 記事のパーマリンクURL | - |
| `published_at`| string | ○ | 公開日時 | UTC基準の ISO 8601形式（`YYYY-MM-DDTHH:mm:ssZ`） |
| `summary` | string | ○ | 記事の概要・本文 | HTMLタグ完全除去・正規化済みのプレーンテキスト |
| `author` | string | - | 著者名 | 取得できない場合は空文字列を設定 |
| `feed_title` | string | ○ | 配信元のフィード名 | 配信元サイトのタイトル |
[cite: 1, 2, 6]

#### 日時パース仕様
- `item.PublishedParsed` を優先して採用し、存在しない場合は `item.UpdatedParsed` を採用する[cite: 1, 5]。
- 取得した日時はすべて UTC タイムゾーンに変換した上で ISO 8601（RFC 3339）文字列としてフォーマットする[cite: 1, 5]。

#### HTMLサニタイズおよびテキスト正規化仕様
`summary` に格納するテキストは以下の処理パイプラインを通じて生成する[cite: 1, 5]。
1. **取得元フィールドの優先度:**
   - `item.Description` を優先採用し、空の場合は `item.Content` をフォールバックとして採用する[cite: 1, 5]。
2. **HTML要素の完全除去（字句解析）:**
   - 正規表現ではなくHTML字句解析トークナイザーを用いてタグを除去する[cite: 1, 5]。
   - `<script>` および `<style>` タグは、タグ自身に加えてタグ内部のテキストコンテンツも含めて完全に破棄する[cite: 1, 5]。
   - ブロック要素（`<p>`, `<div>`, `<h1>`〜`<h6>`, `<li>`, `<br>`, `<article>`, `<section>` 等）の境界には改行コードを挿入する[cite: 5]。
3. **空白および改行の正規化:**
   - 連続する半角空白、全角空白、タブ文字は単一の半角スペースに集約する[cite: 1, 5]。
   - 3つ以上連続する空行・改行は最大2つの改行（`\n\n`）に圧縮する[cite: 5]。
   - テキスト全体の先頭および末尾の不要な空白・改行をトリミングする[cite: 1, 5]。

### 3.5 出力形式仕様

#### JSON出力
- 形式: 共通スキーマに基づいたオブジェクトの配列[cite: 6]。
- レイアウト: 2スペースのインデントを適用した可読性の高いフォーマット[cite: 1]。
- 文字コード: UTF-8[cite: 6]。

```json
[
  {
    "title": "リリースのお知らせ",
    "url": "[https://example.com/articles/1](https://example.com/articles/1)",
    "published_at": "2026-09-30T16:00:00Z",
    "summary": "feed-goのv1.0が正式リリースされました。",
    "author": "管理者",
    "feed_title": "Example Official Blog"
  }
]
```
[cite: 6]

#### CSV出力
- **規格準拠:** RFC 4180に完全準拠[cite: 1, 2, 6]。
- **ヘッダー行:** 1行目に `title,url,published_at,summary,author,feed_title` を常に出力[cite: 1, 2, 6]。
- **エスケープ処理:** カンマ、ダブルクォーテーション（`"`）、および改行コードを含むフィールドは、フィールド全体をダブルクォーテーションで囲み、内部の `"` は `""` にエスケープする[cite: 1, 2, 6]。
- **改行コード:** CRLF（`\r\n`）[cite: 1, 6]。

### 3.6 エラーハンドリングおよび終了コード
処理終了時、プロセスは状況に応じて以下の終了コードを返却する[cite: 1, 2, 6]。

| 終了コード | 状態 | 発生条件 | stderr 出力例 |
| :---: | :--- | :--- | :--- |
| `0` | 正常終了 | すべてのフィード取得・出力が完了 | なし |
| `1` | 引数・オプション不正 | URL未指定、無効なオプション値、フラグ構文エラー | `Error: invalid argument: --format must be either 'json' or 'csv'` |
| `2` | ネットワークエラー | DNS解決失敗、ホスト接続不可、HTTP 4xx/5xx | `Error: network failure: GET https://example.com/feed failed with status 404` |
| `3` | タイムアウト | 接続または読み込みが制限時間（デフォルト10秒）を超過 | `Error: request timed out after 10s` |
| `4` | パースエラー | レスポンスがXML/フィードとして解析不能、未知のフォーマット、空データ | `Error: failed to parse feed from https://example.com/index.html` |
[cite: 1, 2, 6]

## 4. 非機能要件

### 4.1 性能要件
- **起動時間:** プロセス起動から実行完了までのオーバーヘッドを極小化（目標: 起動オーバーヘッド50ms以下）[cite: 1, 6]。
- **メモリ効率:** ストリーム処理を意識し、メモリ使用量は一般的なフィード（数百KB〜数MB）処理時に30MB以下に抑える[cite: 1, 5, 6]。
- **処理速度:** ネットワーク遅延を除き、XML解析および出力変換処理を100ms以内に完了する[cite: 6]。

### 4.2 移植性・運用環境要件
- **動作環境:**
  - Linux（x86_64, aarch64）[cite: 1, 6]
  - macOS（x86_64, arm64 / Apple Silicon）[cite: 1, 6]
  - Windows（x86_64）[cite: 1, 6]
- **配布形態:** 外部ランタイム（JVM、Pythonインタープリタ、Node.js等）を不要とし、依存ライブラリを静的リンク（`CGO_ENABLED=0`）した単一バイナリ形式で配布する[cite: 1, 2, 6]。
- **導入容易性:** OSごとの単一実行ファイルを `PATH` が通ったディレクトリに配置するだけで即座に利用可能であること[cite: 6]。

### 4.3 信頼性・堅牢性
- **リソース解放:** タイムアウトまたはエラー発生時、Goの `context.WithTimeout` を通じてHTTP接続を即座に破棄し、ソケットのリークを防ぐ[cite: 2, 6]。
- **異常入力への耐性:** HTML混入や不正文字が含まれるフィードであっても、プロセスがパニック（異常終了）することなく、安全にサニタイズまたはエラーコードを返却する[cite: 6]。
