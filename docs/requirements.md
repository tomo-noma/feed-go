# コマンドラインフィード取得ツール（feed-go）要件定義書

## 1. システム概要
### 1.1 システム名
コマンドラインフィード取得ツール（実行ファイル名: `feed-go`）[cite: 5]

### 1.2 目的と背景
シェルスクリプト、データパイプライン、定期バッチ処理などの自動化ワークフローに組み込むことを想定し、指定されたWebフィード（RSS/Atom）を高速かつ確実に取得・パースし、JSONまたはCSV形式で標準出力・ファイル出力するCLIツールを開発する[cite: 3, 5]。

### 1.3 利用想定
* **パイプライン連携:** `feed-go [https://example.com/feed.xml](https://example.com/feed.xml) | jq .` のように、後続ツールへストリーム連携する[cite: 5]。
* **定期自動実行:** cronやCI/CDパイプラインによる定期的な情報収集バッチ処理[cite: 5]。
* **データ保管:** オプション指定により直接ファイルへ出力し、アーカイブや分析用データセットを作成する[cite: 5]。

---

## 2. スコープ定義
### 2.1 初期リリース対象（MVP）
* コマンドラインからの単一/複数URL指定によるフィード取得（セマフォによる最大4並行処理）[cite: 2, 5, 11]
* 複数URL指定時におけるエラースキップ（部分成功）制御および終了コード優先度ハンドリング[cite: 2, 6]
* RSS（0.9x, 1.0, 2.0）およびAtom形式のパース[cite: 3, 5]
* 共通データモデルへの正規化（HTMLタグ除去・空白改行正規化を含む）[cite: 3, 5, 7]
* JSONおよびCSV（RFC 4180準拠）形式での出力（標準出力・ファイル出力、入力URL順序保持）[cite: 3, 5, 11]
* 10秒以内のタイムアウト制御およびHTTPリダイレクト制御[cite: 3, 5]
* 規定の終了コード（0〜4）による実行結果の返却[cite: 3, 5, 6]
* GoReleaserとGitHub Actionsによるマルチプラットフォーム（Linux, macOS, Windows）向けの自動アーカイブ配布およびSHA-256チェックサム提供[cite: 2, 10]

### 2.2 対象外（次期フェーズ優先実装）
* **フィード自動検出（Auto-Discovery）:** Webサイト（HTML）の `<link rel="alternate" ...>` タグを解析してフィードURLを特定する機能[cite: 3, 5]。初期版ではフィード（XML）の直接URLのみを受け付ける[cite: 3, 5]。
* **文字コード自動判別・変換:** Shift_JISやEUC-JP等で配信されるフィードのUTF-8自動変換[cite: 3, 5]。初期版はUTF-8配信のフィードのみを対象とする[cite: 3, 5]。

## 3. 機能要件
### 3.1 コマンドラインインターフェース（CLI）
#### コマンド構文

    feed-go [OPTIONS] <URL...>

#### 引数・オプション仕様
| 引数 / オプション | 短縮形 | 引数値 | デフォルト値 | 必須 | 説明 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `<URL...>` | - | 文字列（URL） | - | ○ | 取得対象のフィードURL（1つ以上指定可能） |
| `--format` | `-f` | `json` \| `csv` | `json` | - | 出力フォーマットの指定 |
| `--output` | `-o` | ファイルパス | stdout | - | 出力先ファイルの指定。未指定時は標準出力 |
| `--timeout` | `-t` | 整数（秒） | 10 | - | 1サイトあたりの最大待機時間 |
| `--limit` | `-l` | 整数（件数） | 無制限 | - | 取得・出力する記事数の上限 |
| `--help` | `-h` | - | - | - | ヘルプメッセージの表示 |
| `--version` | `-v` | - | - | - | バージョン情報の表示 |
[cite: 3, 5]

### 3.2 入出力ストリーム制御
パイプライン処理およびシェルスクリプト連携を妨げないため、ストリームを厳格に分離する[cite: 3, 5]。
* **標準出力（stdout） / ファイル出力（`-o`）:** 正常に取得・パースに成功したフィード記事のみを出力する[cite: 2, 6]。複数URL指定時に一部のURLが失敗した場合でも、成功したURLの記事のみを結合して出力する（失敗したURLのデータは含まれない）[cite: 2, 6]。出力記事の順序は、コマンドラインで指定されたURLの入力順序を維持する[cite: 2, 11]。
* **標準エラー出力（stderr）:** 各URLの処理中にエラーが発生した都度、規定のエラープレフィックスを付与して即時出力する[cite: 2, 6]。

### 3.3 フィード取得（ネットワークおよび並行制御）
* **プロトコル:** HTTP / HTTPS[cite: 3, 5]
* **並行実行制御:** 複数URLが指定された場合、Goroutineとバッファ付きチャネル（セマフォ）を用いて最大「4並行」で取得・パースを実行する[cite: 2, 11]。
* **中断制御:** 親の `context.Context`（SIGINT / Ctrl+C等）がキャンセルされた場合、実行中のすべてのGoroutineを即座に破棄してリソースを解放する[cite: 1, 9, 11]。
* **User-Agent:** クライアント側で一意なUser-Agentヘッダーを送信する（形式: `feed-go/<version> (+[https://github.com/](https://github.com/)...)`）[cite: 3, 4, 5]。
* **リダイレクト:** HTTP 3xxリダイレクトを最大5回まで自動追跡する[cite: 3, 4, 5]。6回以上のリダイレクト、または循環リダイレクト時はネットワークエラーとする[cite: 1, 3, 4]。
* **タイムアウト内訳:**
  * 接続確立（Connect）: 最大3秒[cite: 1, 3, 4]
  * レスポンス読み取り（Read）: 最大7秒[cite: 1, 3, 4]
  * 1サイトあたりの合計待機時間は `--timeout` で指定された秒数（デフォルト10秒）を超過しない[cite: 3, 4, 5]。超過時は即座にリクエストを中断し、内部リソースを破棄する[cite: 1, 3, 4]。

### 3.4 フィード解析およびデータスキーマ
取得した各フィード規格（RSS 0.9x, 1.0, 2.0, Atom）の差分を吸収し、以下の統一スキーマに正規化する[cite: 3, 4, 5]。
| フィールド名 | 型 | 必須 | 説明 | 備考 |
| :--- | :--- | :--- | :--- | :--- |
| `title` | string | ○ | 記事タイトル | 前後空白トリミング。空文字の場合は空文字列を設定 |
| `url` | string | ○ | 記事のパーマリンクURL | - |
| `published_at` | string | ○ | 公開日時 | UTC基準の ISO 8601形式（YYYY-MM-DDTHH:mm:ssZ） |
| `summary` | string | ○ | 記事の概要・本文 | HTMLタグ完全除去・正規化済みのプレーンテキスト |
| `author` | string | - | 著者名 | 取得できない場合は空文字列を設定 |
| `feed_title` | string | ○ | 配信元のフィード名 | 配信元サイトのタイトル |
[cite: 3, 4, 5]

#### 日時パース仕様
* `item.PublishedParsed` を優先して採用し、存在しない場合は `item.UpdatedParsed` を採用する[cite: 1, 4, 7]。
* 取得した日時はすべて UTC タイムゾーンに変換した上で ISO 8601（RFC 3339）文字列としてフォーマットする[cite: 1, 4, 7]。

#### HTMLサニタイズおよびテキスト正規化仕様
`summary` に格納するテキストは以下の処理パイプラインを通じて生成する[cite: 1, 4, 7]。
1. **取得元フィールドの優先度:**
   * `item.Description` を優先採用し、空の場合は `item.Content` をフォールバックとして採用する[cite: 1, 4, 7]。
2. **HTML要素の完全除去（字句解析）:**
   * 正規表現ではなくHTML字句解析トークナイザーを用いてタグを除去する[cite: 1, 4, 7]。
   * `<script>` および `<style>` タグは、タグ自身に加えてタグ内部のテキストコンテンツも含めて完全に破棄する[cite: 1, 4, 7]。
   * ブロック要素（`<p>`, `<div>`, `<h1>`〜`<h6>`, `<li>`, `<br>`, `<article>`, `<section>` 等）の境界には改行コードを挿入する[cite: 1, 4, 7]。
3. **空白および改行の正規化:**
   * 連続する半角空白、全角空白、タブ文字は単一の半角スペースに集約する[cite: 1, 4, 7]。
   * 3つ以上連続する空行・改行は最大2つの改行（`\n\n`）に圧縮する[cite: 1, 4, 7]。
   * テキスト全体の先頭および末尾の不要な空白・改行をトリミングする[cite: 1, 4, 7]。

### 3.5 出力形式仕様
#### JSON出力
* 形式: 共通スキーマに基づいたオブジェクトの配列[cite: 3, 5]。
* レイアウト: 2スペースのインデントを適用した可読性の高いフォーマット[cite: 1, 4, 5]。
* 文字コード: UTF-8[cite: 3, 5]。

#### CSV出力
* **規格準拠:** RFC 4180に完全準拠[cite: 3, 4, 5]。
* **ヘッダー行:** 1行目に `title,url,published_at,summary,author,feed_title` を常に出力[cite: 3, 4, 5]。
* **エスケープ処理:** カンマ、ダブルクォーテーション（`"`）、および改行コードを含むフィールドは、フィールド全体をダブルクォーテーションで囲み、内部の `"` は `""` にエスケープする[cite: 3, 4, 5]。
* **改行コード:** CRLF（`\r\n`）[cite: 1, 4, 5]。

### 3.6 エラーハンドリングおよび終了コード
処理終了時、プロセスは状況に応じて以下の終了コードを返却する[cite: 3, 4, 5]。
* **全URL成功時:** 終了コード `0` を返却する[cite: 2, 6]。
* **一部または全URL失敗時（複数URL指定時）:** 発生したすべてのエラーの中で、**最も優先度が高い終了コード**をプロセスの最終終了コードとして返却する[cite: 2, 6]。
* **終了コードの優先度順位:**
  Code 1 (引数不正) > Code 2 (ネットワークエラー) > Code 3 (タイムアウト) > Code 4 (パースエラー)[cite: 2, 6]

| 終了コード | 状態 | 発生条件 | stderr 出力例 |
| :--- | :--- | :--- | :--- |
| **0** | 正常終了 | すべてのフィード取得・出力が完了 | なし |
| **1** | 引数・オプション不正 | URL未指定、無効なオプション値、フラグ構文エラー | `Error: invalid argument: --format must be either 'json' or 'csv'` |
| **2** | ネットワークエラー | DNS解決失敗、ホスト接続不可、HTTP 4xx/5xx、リダイレクト上限超過 | `Error: network failure: GET [https://example.com/feed](https://example.com/feed) failed with status 404` |
| **3** | タイムアウト | 接続または読み込みが制限時間（デフォルト10秒）を超過 | `Error: request timed out after 10s` |
| **4** | パースエラー | レスポンスがXML/フィードとして解析不能、未知のフォーマット、空データ | `Error: failed to parse feed from [https://example.com/index.html](https://example.com/index.html)` |
[cite: 1, 3, 4, 5]

## 4. 非機能要件
### 4.1 性能要件
* **起動時間:** プロセス起動から実行完了までのオーバーヘッドを極小化（目標: 起動オーバーヘッド50ms以下）[cite: 1, 3, 5]。
* **メモリ効率:** 最大4並行のWorker Pool制御を適用し、複数フィード処理時でも常駐メモリ30MB以下を厳守する[cite: 1, 2, 5, 11]。
* **処理速度:** ネットワーク遅延を除き、XML解析および出力変換処理を100ms以内に完了する[cite: 1, 5]。

### 4.2 移植性・運用環境要件
* **動作環境:**
  * Linux（x86_64, aarch64）[cite: 1, 2, 10]
  * macOS（x86_64, arm64 / Apple Silicon）[cite: 1, 2, 10]
  * Windows（x86_64）[cite: 1, 2, 10]
* **配布パッケージ形式:**
  * Linux / macOS: `.tar.gz`[cite: 2, 10]
  * Windows: `.zip`[cite: 2, 10]
* **完全性検証:** 配布アセット全体の改ざん検知および検証のため、`checksums.txt`（SHA-256）を自動生成して添付する[cite: 2, 10]。
* **同梱ファイル:** バイナリ本体（`CGO_ENABLED=0`、`-s -w` による静的リンク）、`README.md`、`LICENSE`[cite: 1, 2, 10]

### 4.3 信頼性・堅牢性
* **リソース解放:** タイムアウトまたはエラー発生時、Goの `context.WithTimeout` を通じてHTTP接続を即座に破棄し、ソケットのリークを防ぐ[cite: 1, 3, 4, 5]。
* **異常入力への耐性:** HTML混入や不正文字が含まれるフィードであっても、プロセスがパニック（異常終了）することなく、安全にサニタイズまたはエラーコードを返却する[cite: 1, 5]。

| :--- | :--- | :--- | :--- |

| **CLIフレームワーク** | `[github.com/urfave/cli/v3](https://github.com/urfave/cli/v3)` | 宣言的構文、標準 `context.Context` 親和性によるタイムアウト制御、拡張性 | ADR-002, ADR-003[cite: 8, 9] |
| **フィードパーサー** | `[github.com/mmcdole/gofeed](https://github.com/mmcdole/gofeed)` (v1.3.0系) | RSS 0.9x/1.0/2.0、Atomを網羅し、日付解析や構造体マッピングが成熟 | ADR-004[cite: 7] |
| **HTMLサニタイザー** | `golang.org/x/net/html` | HTML字句解析（トークナイザー）による `<script>`/`<style>` 除去とタグストリップ | ADR-004[cite: 7] |

| **リリース自動化** | GoReleaser (v2系), GitHub Actions | マルチプラットフォーム向けビルド・アーカイブ・ハッシュ生成の完全無人化 | ADR-007[cite: 2, 10] |
| **標準パッケージ** | `net/http`, `encoding/json`, `encoding/csv` | 外部依存を削減し、RFC 4180準拠のCSV出力や安定したHTTP/JSON処理を実現 | ADR-001[cite: 3, 4] |
